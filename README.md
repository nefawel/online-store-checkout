# Оформление заказа в интернет-магазине

Учебное консольное приложение на C#, которое моделирует заказ физических товаров, цифровых товаров и подписок. Показывает полиморфизм, перегрузку методов и операторов, независимые правила скидок и доставки, а также оплату через интерфейс.

## Запуск

Нужен .NET SDK 10. Оба проекта рассчитаны на `net10.0` и используют только стандартную библиотеку .NET, без внешних NuGet-пакетов.

Выполните из корня репозитория:

```sh
dotnet build OnlineStore.slnx --configuration Release
dotnet run --project src/OnlineStore
dotnet run --project tests/OnlineStore.Tests
```

Последняя команда запускает автономный набор проверок: отдельный консольный проект без тестового фреймворка. При неудачной проверке он завершает работу с ненулевым кодом.

## Демонстрация

Программа создаёт смешанный заказ и использует обе перегрузки `AddProduct`:

| Товар | Цена единицы | Количество | Стоимость позиции |
| --- | ---: | ---: | ---: |
| Механическая клавиатура, 1,2 кг | 5 000,00 ₽ | 2 | 10 000,00 ₽ |
| Курс C#, файл 750 МБ | 1 500,00 ₽ | 1 | 1 500,00 ₽ |
| Облачное хранилище, 12 месяцев по 500 ₽ | 5 400,00 ₽ | 1 | 5 400,00 ₽ |

Для подписки на 12 месяцев уже учтена скидка 10%: `500 × 12 × 0,9 = 5 400 ₽`. Затем к стоимости всех товаров применяется отдельная скидка на заказ 10%.

| Расчёт | Сумма |
| --- | ---: |
| Стоимость товаров | 16 900,00 ₽ |
| Скидка на заказ, 10% | 1 690,00 ₽ |
| Курьер: 300 ₽ + 80 ₽ × 2,4 кг | 492,00 ₽ |
| **Итого: товары − скидка + доставка** | **15 702,00 ₽** |

Показаны успешная оплата картой и оплата наличными: при внесении 20 000 ₽ сдача составляет 4 298 ₽. Это симуляция оплаты; приложение не подключается к банку и не проводит реальные платежи.

В конце программа перехватывает и выводит ошибки для четырёх случаев: количество товара равно нулю, заказ пуст, цифровая доставка выбрана для физического товара и наличных недостаточно.

## Устройство проекта

```text
OnlineStore.slnx
src/OnlineStore/
  Program.cs
  Domain/
    Money.cs
    Products.cs
    Order.cs
  Policies/
    Discounts.cs
    Delivery.cs
  Payments/
    Payments.cs
  Services/
    CheckoutService.cs
tests/OnlineStore.Tests/
```

Основное пространство имён — `OnlineStore`.

| Требование | Реализация |
| --- | --- |
| Денежные значения | Структура `Money` хранит `decimal`, запрещает отрицательные суммы, перегружает `+`, `-` и `*` для целого и дробного множителя, форматирует сумму в рублях. |
| Иерархия товаров | Абстрактный `Product` и классы `PhysicalProduct`, `DigitalProduct`, `SubscriptionProduct` сами определяют стоимость, необходимость доставки и вес. |
| Заказ | `OrderItem` связывает товар с количеством; `Order` содержит позиции, обе перегрузки `AddProduct`, расчёт суммы и физического веса. |
| Скидки | `DiscountPolicy` задаёт общий контракт для `NoDiscount`, `PercentageDiscount` и `FixedDiscount`. |
| Доставка | `DeliveryMethod` задаёт общий контракт для `CourierDelivery`, `PickupDelivery` и `DigitalDelivery`, включая проверку применимости. |
| Оплата | `IPaymentMethod` реализован классами `CardPayment` и `CashPayment`; наличная оплата проверяет сумму и рассчитывает сдачу. |
| Оформление | `CheckoutService` проверяет заказ и доставку, рассчитывает стоимость товаров, скидку, доставку и итог. |
| Демонстрация | `Program.cs` выводит состав заказа, расчёт, оплату и обработку ошибочных сценариев. |

Сервис оформления использует абстракции скидки и доставки. Цена и характеристики товаров получаются полиморфно, без проверок конкретного типа товара.

## Правила расчёта

- Денежные результаты округляются до двух знаков по правилу `MidpointRounding.AwayFromZero`.
- Скидка подписки 10% применяется к её полной стоимости при сроке от 12 месяцев. Скидка на заказ рассчитывается отдельно от суммы товарных позиций.
- Процент скидки допустим от 0 до 100 включительно. Фиксированная скидка больше стоимости товаров вызывает исключение.
- Курьерская доставка рассчитывается пропорционально весу, включая дробную часть килограмма.
- Курьер и самовывоз доступны заказам хотя бы с одним физическим товаром. Цифровая доставка доступна заказам без физических товаров; подписки также не требуют физической доставки.
- В смешанном заказе стоимость доставки зависит только от физических товаров. Цифровые товары и подписки не увеличивают вес.
- Некорректные суммы и параметры, вычитание с отрицательным результатом, неподходящая доставка, пустой заказ и недостаток наличных обрабатываются исключениями.
